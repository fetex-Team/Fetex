# 03. 배차 비용: 다익스트라 도로 이동시간

파일: `module4_dispatch/network_cost.py`, `module4_dispatch/hungarian_dispatcher.py` / 설정: `config.json` → `"dispatch_cost": "network"`

---

## 문제

| 관찰 | 수치 |
|---|---|
| 손님 대기 = 배정된 택시가 손님까지 가는 시간 (배정은 호출 즉시) | 순찰 기준 배차 후 픽업까지 평균 77.3초 ≈ 평균 대기 77.0초 |
| 전략 간 대기 차이도 전부 이 이동 시간에서 나옴 | 순찰 77.3 / 선배치 83.0 / RL 86.4초 |
| 그런데 헝가리안 비용이 **직선 거리**(택시 좌표 ↔ 승객 도로 시작점) | |
| 강남역 일대는 일방통행·유턴 제한·좌회전 금지가 많음 | 무작위 표본 300건: 직선 최근접 택시 ≠ 도로 최단시간 택시인 경우 **40%**, 그때 평균 **+17초** (신호 대기 제외) |

## 결정

헝가리안 알고리즘은 그대로 두고, 비용만 **도로망 최단 이동시간**으로 바꾼다.

1. 시작할 때 한 번: 일반 도로 406개 각각에서 다익스트라로 "이 도로 끝 → 다른 도로 시작" 최단 시간 표를 만든다 (0.4초).
   - 간선 = 실제 차선 연결(회전 허용, vClass=taxi). 비용 = 교차로 내부 차선 통과 시간 + 다음 도로 전체 통과 시간, 속도는 제한속도
2. 배차 때: 택시(도로 a, 위치 pa) → 승객(도로 b, 위치 pb)
   - 같은 도로이고 앞쪽: `(pb − pa) / v_a`
   - 그 외: `(len_a − pa)/v_a + D[a][b] + pb/v_b`
3. 갈 수 없는 조합은 1e6초(+직선 거리)로 두어 배정되지 않게 한다

## 근거 (7일, 같은 손님)

| 전략 | 평균 대기: 직선 → 도로 | 놓친 손님/일 (손님 100%) |
|---|---|---|
| 순찰 | 80.6 → **60.1초** | 306 → **266** |
| 시간표 선배치 | 86.5 → 69.6초 | 306 → 315 |
| RL | 91.2 → 75.5초 | 316 → 330 |

- 세 전략 모두 평균 대기 10~20초 단축, 순찰은 7일 모두 단축
- 7일 동안 도달 불가 조합이 배정된 경우 0건

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 배차 때마다 `traci.simulation.findRoute` 호출 | 스텝마다 택시 × 손님 수만큼 TraCI 왕복 → 수 배 느려짐 |
| 직선 거리 × 우회 계수 | 일방통행 방향 문제를 못 잡음 (같은 직선 거리라도 방향에 따라 시간이 크게 다름) |
| 실시간 정체 반영 | 후속 과제 (현재 남은 작업 2번) |

## 검증

- `tests/test_network_cost.py`: 일방통행 고리 도로망을 만들어 우회 시간, 같은 도로 앞/뒤, 도달 불가 처리 확인
- sumolib 최단경로와 500쌍 비교: 이 표의 값이 sumolib(교차로 내부 제외)보다 작거나 도달 불가로 나온 경우 0건
- 기본값 변경 전 `"dispatch_cost": "euclidean"`으로 예전 결과가 숫자까지 재현됨

## 한계

- 자유 흐름(제한속도) 시간이라 신호 대기·정체가 빠져 실제보다 짧다. "어느 택시가 더 빨리 가나" 비교에는 충분
- 택시가 교차로 안에 있으면 다음 도로 시작에 있다고 본다
