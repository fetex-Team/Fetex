# jwy 브랜치 정리 — 팀 공유 (2026-11-12)

원격 `jwy`에 ldk(11/8까지)와 KJS(11/12까지) 변경을 모두 검토해 합친 통합본이에요.

## 받은 뒤 먼저 할 것
```bash
pip install -r requirements.txt
```
- 대시보드용 `flask`가 추가됐어요.
- 내 설정 `config.json`은 git에 안 올라가요(개인 파일). 없으면 팀 기본값 `presets/default/기본.json`으로 시작해요.
- 실행: `python config_gui.py`(설정 화면) 또는 `python main.py <명령>`

## 1. 구조 정리
과제 결과물 구조대로 나누고, 모듈 안에 하위 폴더를 만들었어요.

| 폴더 | 역할 |
|---|---|
| `data/loaders/` | 데이터 만들기·받기 (실측 통계 → 호출 로그, 날씨, 신호, TOPIS, 생활인구) |
| `module1_simulation/` | 디지털 트윈. `unity/` 재생 파일, `checks/` 검증 도구 |
| `module2_preprocessing/` | 전처리(피처 43개). `eda/` 분석 코드 |
| `module3_prediction/` | 학습·평가·실시간 예측 |
| `module4_dispatch/` | 배차·재배치·RL. `experiments/` A/B·반복 실험 |
| `dashboard/` | 웹 대시보드 |
| `tools/` | 여러 모듈이 같이 쓰는 도구 (모델 세트 보관함, 학습 기간 타임라인 등) |
| `results/` | 결과물 (`module3/`, `eda/`, `repeat/` 등) |

- `scripts/`, `eda/` 폴더는 없어졌어요. 예: `python scripts/generate_demand_logs.py` → `python data/loaders/generate_demand_logs.py`
- 폴더별 설명은 `README.md`의 "폴더 구조"에 있어요.

## 2. 실행 방법
| 하고 싶은 것 | 명령 |
|---|---|
| 설정 화면 | `python config_gui.py` (기본·세부 2탭, 프리셋 버튼, 항목에 마우스 올리면 설명) |
| SUMO로 보기 | `python main.py play` |
| 학습 | GUI "학습만 실행" 또는 `python main.py train` (지도 → 로그 → 수요 예측 → 카테고리 모델 → RL) |
| 실측 기간으로 학습 | `python main.py train --real-start 2026-07-13 --real-end 2026-09-06` (`--rl-only`: RL만) |
| 수요 예측만 | `python module3_prediction/train.py --logs "data/real_demand_logs/demand_log_*.csv"` (5분: `--freq 5min`) |
| A/B 비교 | GUI "A/B 비교하기" (실행 날짜 지정, 모델 세트 선택, 동시 4개까지 대기열) |
| 대시보드 | `python main.py dashboard` |

- GUI 실행 버튼은 `config.json`을 바꾸지 않아요. [적용하기]를 눌러야 저장돼요.
- 기본값은 `presets/default/기본.json` 한 곳에만 있어요.

### GUI 정리 (11/12)
- **세부 탭**: 실측 모드 기준으로 섹션 7개, 항목 33개만 보여요.
  - 학습 설정은 "학습만 실행" 창으로, 동시 실행 수는 A/B 창으로, Unity 경로는 Unity 창으로 옮겼어요.
  - 수요 출처가 real이면 가정 모델 섹션은 숨겨요. 거의 안 바꾸는 값은 섹션마다 "고급"으로 접었어요.
  - 설정 파일 형식은 그대로라서, 기존 `config.json`·프리셋을 그대로 쓸 수 있어요.
- **"학습만 실행" 창** (KJS 학습 창 기능을 옮김)
  - 학습 범위: 전체 / RL만
  - RL 보상 방식: default / gravityVer
  - 학습 데이터: 실측 통계 기간을 타임라인에서 고르기(2·4·8주, 평가 날짜와 겹치면 경고) / 시뮬레이션 로그 고르기
- **모델 세트 보관함** (백업 + KJS 스냅샷 통합)
  - 학습할 때마다 이전 모델 한 벌이 `saved_models_backups/<시각>/`에 자동 보관돼요. 수요 예측, 카테고리, RL 모델, 학습 조건 메모(택시 수·보상 방식·학습 기간)가 같이 들어가요.
  - A/B 창의 [지금 모델 보관...] / [이름 붙이기...]로 좋은 세트에 이름을 붙여요.
  - A/B 창에서 세트를 고르면 그 세트의 모델로 비교해요.

## 3. Module 3 (수요 예측) — 담당
학습 모델은 '같은 시각 평균'과 같은 수준이에요. 통계로 만든 데이터라 시각 패턴 밖의 신호가 거의 없기 때문이고, 보고서에 그대로 적었어요(REPORT 부록 B).

- XGBoost·CNN-LSTM이 **t+1~t+6을 동시에 예측**해요. 학습/검증/시험 시간순 분할, 조기 종료, GridSearch 튜닝을 써요.
- `train.py` 하나가 시뮬레이션용 `demand_v2`까지 만들어요(예전 `train_dispatch_model.py` 통합).
- 실시간 예측 코드도 Module 3로 옮겼어요: `h3_predictor.py`(forecast용), `category_predictor.py`(RL용)

결과 (11/12 재학습, 56일 실측 보정 로그, 시험 구간):

| 모델 | 칸별 WAPE | 30분 합계 WAPE |
|---|---:|---:|
| 같은 시각 평균 (기준) | 26.0% | 15.7% |
| XGBoost 10분 (시뮬레이션용) | 26.3% | 16.3% |
| CNN-LSTM 10분 | 26.7% | 16.9% |
| XGBoost 5분 (과제 기준) | 36.0% | 16.4% |
| 나이브 (기준) | 36.2% | 29.7% |

그래프·지표는 `results/module3/<5min|10min>/`에 있어요.

## 4. 다른 브랜치에서 합친 것
- **ldk (11/8):** 도로 현실화(실제 신호, 5030, 버스 전용 차로, TOPIS 속도), 생활인구 승차 위치, 대시보드, 검증 도구 10개, REPORT §5.8·5.9
  - **기본값은 그대로 두고**, ldk 설정은 **"근거기반_현실화" 프리셋**으로 넣었어요(GUI 기본 탭 버튼). 택시 61대, 대기 600초.
- **KJS:**
  - RL 개선: 예측 입력을 새 호출·10분 칸으로, 보상 방식 선택(default/gravityVer), 관측 정규화
  - 택시 막다른 길 회피(소멸 17 → 0대), A/B 대기열·실행 날짜 지정, 데이터 품질 검사, WinError 1114 방지
  - 학습 창(보상 선택, 실측 기간 타임라인, RL만 학습), 모델 스냅샷(→ 모델 세트 보관함으로 통합)

### 가져오지 않은 것과 이유
| 출처 | 항목 | 이유 |
|---|---|---|
| ldk | 모델 파일(`saved_models/`), RL 모델과 중간 저장본 | 모델 파일은 손상돼 열리지 않고, 형식과 RL 입력 방식도 jwy와 달라요. jwy에서 다시 학습함 |
| ldk | 새로 만든 지도 파일 | jwy 지도를 유지해요. 프리셋으로 실행하면 그때 새로 만들어요 |
| ldk | 기본값 변경(택시 61대, 대기 600초 등) | 기본값은 유지하고, ldk 값은 "근거기반_현실화" 프리셋으로 넣었어요 |
| ldk | 속도 보정 중간 결과, 대시보드 테스트 결과 | 보고서·대시보드에서 안 쓰는 중간 산출물 |
| KJS | 카테고리 라벨을 **목적지** 기준으로 | 재배치는 손님이 **타는 곳**이 중요해서 승차 위치 기준으로 통일했어요. KJS 코드는 실측 수요 모드에서 라벨이 비는 버그도 있었어요 |
| KJS | GUI 일부 (로그 날짜 자동 선택, 로그 복사, 데이터 품질 검사 버튼) | jwy GUI는 2탭으로 새로 짜서 그대로는 안 맞아요. 나머지 GUI 기능은 다시 만들어 넣었고, 이 3개는 아직이에요 |
| KJS | 병합하면서 생긴 버그 (수요 배율이 1.0으로 덮어써짐, import 누락, 측정 루프 되돌림, RL 학습 날짜 범위 미적용) | 버그라서 제외. KJS 브랜치에서도 고치는 게 좋아요 |
| KJS | 모델 파일, 스냅샷 폴더 | H3 해상도·피처 수가 jwy와 달라서 못 써요. 스냅샷 폴더는 RL 모델 zip이 git에 안 올라가 실제로는 비어 있어요 |
| KJS | Unity 재생 파일 키 이름 변경(`points` → `boundary`) | Unity 쪽 읽기 형식과 충돌해요. Unity 담당과 맞춘 뒤 결정 |
| KJS | 개인 설정, 프리셋, 임시 스크립트(`scratch/`), 실험 결과(11/12 고정 7일 A/B 포함) | 개인 실험용. 7일 결과는 KJS 코드 기준이라 jwy에서 같은 조건으로 다시 돌려 확인할 예정 |

## 5. 고친 주요 버그
- 시간 초과 승객이 실제로는 안 사라지던 문제(보호 명단이 계속 쌓임)
- RL 입력이 학습과 달랐던 문제 3가지 + 시간 피처 + 공휴일 판정 불일치
- RL 실행 결과가 매번 달라지던 문제(난수 시드)
- forecast 예측이 최근 칸을 버리던 문제, 기준 모델 정렬 오류, 학습/시험 경계 누수
- GUI 학습 버튼이 깨져 있던 import, A/B 날짜가 "오늘"로 잡히던 문제, Unity 경로 하드코딩
- 예전 가짜(목업) 데이터로 `demand_v2`를 덮어쓰던 문제
