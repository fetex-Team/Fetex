# 날씨-수요 계수 추정 결과

Module 2 외부 데이터 결합의 근거 자료. 시뮬레이션 승객 생성에 주입할
기온·강수 반응 계수를 **실측 데이터로 추정**한 기록이다.

작성: 2026-09-12 / 담당: 이동규 (지도·외부데이터)

---

## 1. 왜 추정하는가

SUMO 시뮬레이션의 승객 생성은 시각과 POI 확률로만 결정되고 날씨와 무관하다.
그 상태로 날씨 피처를 붙이면 수요와 상관계수가 0이 되어 모델이 아무것도 학습하지 못한다.

반대로 "비 오면 승객을 늘린다"는 규칙을 임의의 숫자로 넣으면, 모델이 주입한 값을
다시 학습하는 순환논리가 된다.

그래서 **증가율을 실측 데이터에서 추정**하고, 그 값을 시뮬레이션에 주입한다.
계수의 출처가 외부 데이터이므로 순환논리가 아니다.

## 2. 데이터

| 항목 | 내용 |
|---|---|
| 수요 | 서울 열린데이터광장 「수도권 생활이동 (연령별, 출발-도착지 기준)-내국인」 |
| 기간 | 2026-08-10 ~ 2026-08-31 (연속 22일) |
| 공간 범위 | 강남구 출발 (행정동 코드 `11680*`, 22개 행정동) |
| 날씨 | 기상청 지상(종관 ASOS) 시간자료, 서울 지점번호 108 |
| 표본 | 시간 단위 528개 (22일 x 24시간) |
| 강수 발생 | 전체 시간의 9.5% (50/528) |

### 시간 코드 처리

생활이동 데이터의 `st_time_cd`는 시간대에 따라 단위가 다르다.

- 비첨두(00-06, 10-16, 20-23): 2자리 시 단위 (`02`)
- 첨두(07-09, 17-19): 4자리 20분 단위 (`0720`)

ASOS가 시간 단위이므로, 첨두의 20분 코드 3개를 해당 시로 합산해 시 단위로 통일했다.
이것이 "시공간 단위가 다른 외부 데이터를 결합하는 전처리 로직"에 해당한다.

## 3. 모형

종속변수는 시간대별 총 이동인구의 자연로그. 시간과 요일을 고정효과로 통제한다.

```
ln(trips) ~ C(hour) + C(dow) + rain + temp
```

시간·요일을 통제하는 이유: 출퇴근 피크와 주말 패턴이 수요 변동의 대부분을 설명하므로,
이를 빼지 않으면 날씨 계수가 시간대 효과를 흡수한다.

## 4. 결과

n = 528, R² = 0.972

| 변수 | 효과 | 95% 신뢰구간 | p |
|---|---|---|---|
| 강수 여부 (>0.1mm) | **+6.79%** | -0.03% ~ +14.08% | 0.051 |
| 강수량 1mm당 | **+1.99%** | +0.23% ~ +3.79% | 0.027 |
| 기온 1°C당 | **+2.73%** | +1.72% ~ +3.76% | <0.001 |

### 해석

- **강수량(연속)이 더 신뢰할 만하다.** 강수 여부 더미는 p=0.051로 경계선이고
  신뢰구간이 0을 걸친다. 반면 강수량을 연속값으로 쓰면 p=0.027로 유의하다.
  비가 왔는지보다 **얼마나 왔는지**가 수요를 움직인다.
- 기온 계수는 통계적으로 강하지만 8월 22일치라 변동 범위가 좁다(21.5~34.3°C).
  겨울 데이터가 없으므로 **여름철 한정 계수**로 취급해야 한다.

## 5. 한계 (보고서에 반드시 명시)

1. **이 데이터는 택시 호출이 아니라 전체 이동인구다.** 수단 구분 컬럼이 없어
   택시만 분리할 수 없다. 따라서 위 계수는 택시 수요 탄력성의 *대리 지표*다.
   수단별 데이터(「수도권 생활이동 - 도착 행정동 기준 시간대별 성연령별 수단 데이터」)로
   교체하면 이 한계가 해소된다.
2. 22일, 여름 한 달이라 계절 일반화가 불가능하다.
3. 기온과 강수는 서로 상관된다(비 오는 날이 서늘하다). 두 계수를 독립적으로
   해석할 때 주의가 필요하다.

## 6. 시뮬레이션 적용 방식

`passenger_spawn_manager.py`의 승객 생성 확률에 곱할 배수:

```
weather_multiplier = (1 + 0.0199) ** precip_mm * (1 + 0.0273) ** (temp - temp_base)
```

`temp_base`는 해당 시뮬레이션 기간의 평균 기온.
config.json이 아니라 별도 파라미터 파일로 분리해 팀 공유 설정을 건드리지 않는다.
